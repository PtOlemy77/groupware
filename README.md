# SpatialT 그룹웨어

Next.js 15 / React 19, Spring Boot 3.4 / Java 21 이상, PostgreSQL 16 기반입니다. 브라우저는 동일 출처 `/api`만 사용하며 Next.js가 백엔드로 프록시합니다.

## 개발 실행

1. Java 21 이상, Node.js 22, Docker를 준비합니다.
2. `.env.example`을 `.env`로 복사하고 DB·최초 관리자 비밀번호를 실제 값으로 변경합니다. 비밀번호는 12자 이상이어야 합니다. `.env`는 Git에서 제외됩니다.
3. 터미널에 환경변수를 불러옵니다. 예: `set -a; source .env; set +a`
4. `docker compose up -d postgres`
5. `cd backend` 후 `./mvnw spring-boot:run`
6. 별도 터미널에서 프로젝트 루트의 `npm ci`, `npm run dev`를 실행합니다.
7. http://localhost:3000 에서 `BOOTSTRAP_ADMIN_EMAIL`과 지정한 비밀번호로 로그인합니다. 최초 로그인 시 비밀번호를 변경해야 합니다.

Maven이 없으면 `backend/mvnw`가 고정 버전의 Maven을 내려받고 SHA-512를 검증합니다. 특정 IDE·JDK 경로에 의존하지 않습니다. 이미 설치된 Maven이나 `JAVA_HOME`은 그대로 사용할 수 있습니다.

## 기존 DB 업그레이드와 계정 복구

- **먼저 백업을 만드세요.** 초기화기는 직원·프로젝트·계약·평가·자산을 삭제하거나 예제 데이터로 덮지 않습니다.
- Flyway V1은 기존 행을 보존하면서 버전·감사 시각·관계 ID·연도별 매출·보안 컬럼, 날짜 타입, FK·고유성·범위 제약을 추가합니다. 프로젝트 PM·인력, 평가 대상, 문서 작성자·프로젝트의 기존 이름/사번은 유일하게 식별되는 경우에만 연결합니다.
- 기존의 중복 이메일·잘못된 날짜·고아 참조 등으로 제약을 적용할 수 없으면 마이그레이션 전체가 실패합니다. 원본 행은 삭제하지 않습니다. 모호한 동명이인·매칭되지 않는 과거 자료는 관리자가 실제 ID를 확인해 연결해야 합니다.
- 기존 평문 비밀번호는 BCrypt로 전환합니다. 짧은 비밀번호(기존 `1234` 포함)·비밀번호가 없는 계정은 비활성화합니다. 공통 우회 비밀번호는 없습니다.
- 활성 시스템 관리자가 없을 때만 `BOOTSTRAP_ADMIN_EMAIL/PASSWORD`로 관리자 계정을 만들거나 지정한 재직 계정을 복구합니다. 이미 활성 관리자가 있으면 재시작으로 비밀번호를 덮어쓰지 않습니다. 복구 후 해당 환경변수를 제거하세요.
- 관리자는 직원 관리에서 각 계정의 비밀번호를 재설정할 수 있습니다. 재설정하면 계정이 활성화되고 기존 세션이 폐기되며 다음 로그인에서 변경을 요구합니다. 직원은 이력 보존을 위해 삭제 대신 퇴사·비활성 처리합니다.
- 이전 JSON 형식을 해석할 수 없는 계약은 원본을 자동으로 빈 문서나 예제로 대체하지 않습니다. 원본을 보존한 채 별도 변환해야 합니다.

## 업무 규칙

- 일반직원은 소속 프로젝트·자산·본인 평가를 조회합니다. 연락처·연차 등 다른 직원의 개인정보와 계약 원가 본문은 제한됩니다.
- PM은 본인이 담당하는 프로젝트·계약·보고를 작성합니다. 직원 계정·권한은 시스템 관리자만 변경합니다. 인사평가·자산·기준정보는 임원/관리자가 관리합니다.
- 계약은 **작성중 → 결재대기 → 승인완료/반려** 순서입니다. 지정된 임원만 최종 결재할 수 있고 자기 결재는 금지합니다. 상신/승인 문서는 잠기며 승인 문서는 개정본을 만들어 수정합니다. 승인 원문은 프로젝트 변경으로 덮지 않습니다.
- 프로젝트의 `budget`은 전체 계약금액(만원), `share_rate`는 당사 지분율, `our_budget`은 서버가 계산하는 당사 금액(만원)입니다. 계약 `supplyAmount`와 원가 항목은 천원입니다. 입력된 항목의 합계·공수·이익·VAT는 서버에서 재계산합니다.
- 프로젝트·계약 연동과 영업→프로젝트 전환은 단일 DB 트랜잭션입니다. 같은 영업은 한 번만 전환되며 전환된 영업은 프로젝트 매출에 중복 가산하지 않습니다.
- 연도별 수기 배분은 전체 금액 합계와 기간을 검증하고 저장합니다. 기간 밖 연도의 매출·공수는 0이며 미입력 공수를 임의의 1 M/M으로 집계하지 않습니다.
- 노임단가·목표매출은 서버에 저장되어 공유됩니다. 초기값은 미설정/0이며 신규 인력은 적용 연도의 저장된 단가를 사용합니다. 기존 계약 단가는 당시 스냅샷으로 보존합니다.
- 모든 수정·삭제는 조회 당시 `version`이 필요합니다. 충돌은 409로 반환하고 입력을 자동 덮어쓰지 않습니다. 보고서도 같은 기간의 동시 편집을 감지하며 PM 저장은 다른 PM의 항목을 보존합니다.
- 목록은 화면 범위로 나누어 조회하며 큰 계약 시트는 상세 열기 시 가져옵니다. 결재·영업·평가·자산 목록은 기본 50건 단위입니다. 목록 검색·정렬은 현재 페이지에 적용됩니다. 직원/프로젝트 요약은 인력 선택과 집계를 위해 함께 제공됩니다.

## 인증·운영

- 서버 세션, HttpOnly·SameSite=Strict 쿠키, CSRF 검증을 사용합니다. 역할·계정 상태·자격 버전을 매 요청에서 확인합니다. 유휴 30분·최대 12시간, 계정당 세션 3개, 계정/IP별 로그인 시도 제한이 적용됩니다. 비밀번호·권한·상태 변경으로 기존 세션이 폐기됩니다.
- 브라우저 저장소에 인증·비밀번호·회사 기준정보를 넣지 않습니다. 비밀번호 해시도 API 응답과 감사 스냅샷에서 제외합니다. 로그아웃은 서버 세션을 폐기합니다.
- 운영은 HTTPS 앞단에서 프런트를 제공하고 백엔드·DB는 내부 네트워크에서만 접근시키세요. `SPRING_PROFILES_ACTIVE=prod`는 Secure 쿠키와 Flyway의 자동 baseline 금지를 적용합니다. 기존 DB의 첫 업그레이드만 백업·검증 후 `SPRING_FLYWAY_BASELINE_ON_MIGRATE=true`와 baseline 0을 명시적으로 사용합니다.
- `API_INTERNAL_URL`은 Next.js 서버용 주소입니다. 기본값은 개발 백엔드의 `http://127.0.0.1:8080`입니다. 포트를 변경하면 프런트 빌드에도 같은 값을 전달하세요.
- PostgreSQL 개발 포트는 `127.0.0.1:5433`에만 게시합니다. 운영 DB 암호·주소는 환경변수로 지정하고 SQL 본문/바인딩 로그는 켜지 마세요.
- 감사 이벤트에는 요청자 ID, 모듈, 작업, 대상 ID, 서버 시각, 변경 후 스냅샷이 남습니다. 감사 테이블을 변경하는 API는 없습니다. 운영 DB 계정의 권한·백업 보존 정책은 배포 환경에서 별도로 설정해야 합니다.

## 검증

```sh
npm run typecheck
npm test
npm run build
npm audit --audit-level=high
cd backend
./mvnw verify
```

Node 테스트는 매출·공수 계산과 PostgreSQL 엔진(PGlite)을 사용한 신규/기존 스키마 이행·롤백을 검사합니다. Java 통합 테스트는 격리된 H2에서 인증·CSRF·세션·역할·개인정보·버전 충돌·결재·트랜잭션 롤백·기준정보·보고서·페이지 응답을 확인합니다. 실제 운영 DB에는 테스트 데이터를 넣지 않습니다.

## 백업·복구 예시

```sh
mkdir -p backups
docker compose exec -T postgres pg_dump -U nexus -Fc groupware_db > backups/groupware.dump
```

복원 검증은 기존 DB에 덮어쓰지 말고 별도 검증 DB에 수행합니다. 예를 들어 별도 PostgreSQL 인스턴스에서 `createdb -U nexus groupware_restore_check` 후 `pg_restore -U nexus -d groupware_restore_check backups/groupware.dump`를 실행하고 행 수·계정·계약·평가·문서 관계를 확인하세요. DB 복원과 Flyway 이행은 검증 환경에서 먼저 실행한 뒤 운영에 적용합니다.

브라우저 전체 흐름 검사는 `npx playwright install chromium` 후 `npm run test:e2e`로 실행합니다. 사용 중이지 않은 13000·18080 포트와 새 H2 메모리 DB를 사용하며 로그인·비밀번호 변경·프로젝트·계약창·빈 보고서·모바일 메뉴·세션 복원·로그아웃을 검사합니다. 기존 Chrome을 사용할 때는 `BROWSER_EXECUTABLE`에 실행 파일 경로를 지정할 수 있습니다. 테스트 서버는 완료 후 종료됩니다.
