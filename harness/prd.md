# SPATIAL T 포털·그룹웨어 요구사항

- 기준일: 2026-11-03 / 문서 버전: 1.2
- 범위: 공개 기업 포털, 개인정보 안내, 공지사항, 인증된 임직원 그룹웨어.
- 작업 불변식은 [AGENTS.md](../AGENTS.md), 검증은 [하네스 기준](HARNESS_ENGINEERING.md)을 따른다.

## 상태의 의미

**구현**은 코드가 존재한다는 의미이며 이번 작업의 모든 환경에서 검증됐다는 뜻이 아니다. **부분 구현**은 제한이 있는 상태다. **계획**은 제공 중인 기능으로 안내하지 않는다. 실제 검증 결과는 실행 로그와 변경 보고로 확인한다.

| `ROLE_PM` | PM | 허용된 프로젝트·계약·보고 작성, 소속 프로젝트 수행평가 조회, 담당 PM·지정 인재풀 검토자일 때 목표 승인·실적 평가 |

## 코드와 데이터 계약

- 고정 코드: `RoleCode`, `PositionCode`, `DepartmentCode`, `StatusCode`, `ProjectStageCode`. 표시용 라벨을 업무 판정에 사용하지 않는다. 과거 입력을 코드로 바꾸는 경계 변환은 별도 구분한다.
- 관리자 편집 기준정보: `common_codes`의 일반 코드·연도별 단가·목표 등. 실제 그룹 키는 서버가 사용하는 `DEPARTMENT`, `POSITION`, `USER_ROLE`, `MASTER_PRICES`, `MASTER_TARGETS` 등을 확인한다. 고정 시스템 코드 그룹은 일반 CRUD로 변조하지 않는다.
- 최신 스키마는 [Flyway](../backend/src/main/resources/db/migration), 관계 요약은 [DB 안내](../export/DATABASE_SPECIFICATION.md), 프론트 모델은 [groupware.ts](../src/types/groupware.ts)를 확인한다.
- 프로젝트 금액은 만원, 계약 원가는 천원. 기간 밖 매출·공수는 0. 미입력은 추정 실적으로 바꾸지 않는다.
- 이름·부서명은 표시·이력 값이며 PK/FK의 대체 수단이 아니다. 읽기 전용 감사 이벤트는 일반 편집 엔티티와 구분한다.

## 수행평가 운영 범위

- [수행평가 서비스](../backend/src/main/java/com/nexus/groupware/domain/evaluation/service/EvaluationPlanService.java)와 [전용 모델](../src/types/evaluation-plans.ts)을 기준으로 한다. 프로젝트 기본 배점은 35/35/30, 인재풀 기본지표는 5개 각 10점이며 승인 업무 지표를 추가해 총 100점 이내로 설정한다. 목표 제출 전에 항목·배점을 정하고 승인 후에는 고정한다.
- PM은 목표를 직접 덮어쓰지 않고 보완을 요청한다. PM 본인의 프로젝트 목표나 담당 PM 미지정 건은 임원 검토자를 지정한다. 평가 확정 후 결과·점수도 수정할 수 없다.
- 프로젝트 변경 저장 시 새 배정 이력을 만들며, 기존 목표·승인 이력은 보존한다. 서버 기동이나 GET 조회에서 기존 업무 데이터를 다시 쓰지 않는다. V8은 새 테이블과 최초 배정 이력만 추가한다.
- 기능 복귀는 백엔드 `EVALUATION_PLANS_ENABLED=false` 설정 후 재시작·화면 새로고침으로 수행한다. 기존 평가 화면으로 돌아가며 새 평가 기록과 적용된 V8 마이그레이션 파일·이력은 보존한다. 소스 기준 태그는 `before-quant-evaluation-20261103`, 변경 버전 태그는 `quant-evaluation-v1-20261103`이다. 태그는 DB 백업을 대신하지 않는다.

## 비기능 요구와 미검증 항목

- 나라장터 연동 설정·알림 범위·호출량 및 운영 준비는 [입찰공고 연동 안내](PROCUREMENT.md)를 따른다. 인증키가 없으면 관심조건 등록은 가능하지만 새 공고를 자동 수신하지 않는다. 알림은 그룹웨어 내부에 저장하며 외부 이메일·문자·브라우저 푸시 발송은 제공하지 않는다.

- React 19/Vite, Spring Boot 3.4.5, Java 21 이상, PostgreSQL 16을 지원 기준으로 한다.
- 빌드 시간·초기 로드 시간을 특정 PC 측정 없이 수치로 보장하지 않는다. 성능 목표를 설정할 때는 장비·네트워크·데이터량·측정 지표·반복 횟수와 기준값을 함께 정한다.
- 데스크탑·모바일 자동 검사 외에도 태블릿, 키보드·스크린리더, 큰 데이터 표 가독성은 UI 변경 시 검증 범위를 기록한다.
- 운영 TLS·프록시·DB 권한·로그 보관·백업 복원·개인정보 담당자는 배포 환경에서 확인한다. 코드 테스트 통과로 운영 검증을 대신하지 않는다.
- 과거 실명·계정·인사평가·계약 데이터는 PRD와 테스트 자료에 포함하지 않는다.
