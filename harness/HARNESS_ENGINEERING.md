# 하네스 엔지니어링 기준

공개 포털과 임직원 그룹웨어의 변경을 재현 가능한 명령과 회귀 테스트로 검증한다. 테스트 통과는 검사한 범위의 근거이며, 모든 결함의 부재나 운영 배포 완료를 보장하지 않는다.

## 단일 실행 경로

저장소 루트에서 실행한다. Node.js 22 이상, Java 21 이상, 설치된 npm 의존성이 필요하다.

```sh
npm ci
npm run verify
# 최초 브라우저 준비 후 전체 게이트
npx playwright install chromium
npm run verify:full
```

정의는 [verify.mjs](../scripts/verify.mjs)에만 둔다. 문서마다 별도 필수 명령 목록을 복제하지 않는다.

| 순서 | 게이트 | 확인 내용 |
| --- | --- | --- |
| 1 | `npm run check:harness` | 네이티브 alert/confirm 참조, 개인 추출본 Git 추적, 공유 문서의 해시·깨진 파일 링크 검사 |
| 2 | `npm run typecheck` | 프론트 타입 검사 |
| 3 | `npm test` | 금액·연도·공수, PostgreSQL 엔진 기반 마이그레이션·보존, 하네스 검사기의 거절 사례 |
| 4 | Maven `verify` | H2 기반 API 인증·권한·버전·트랜잭션·초기화 보존·공지 공개 범위, JAR 패키징 |
| 5 | `npm run build` | Vite 프로덕션 빌드 |
| 6 | 전체 모드의 `npm run test:e2e` | Vite preview와 격리 H2 기반 공개 포털·인증·탐색·공지·모달·직원 조직도 및 주요 업무 화면의 검색·선택·이동·저장·모바일·세션 |

개별 게이트를 진단 목적으로 실행해도 된다. Maven을 직접 실행할 때는 루트 기준 `./backend/mvnw -f backend/pom.xml verify`를 사용한다. `compile` 또는 `test-compile -DskipTests` 성공은 테스트 통과가 아니다.

[CI](../.github/workflows/ci.yml)는 JDK 21에서 전체 게이트와 `npm audit --audit-level=high`를 실행한다. 로컬 네트워크·브라우저 부재 등으로 미실행된 검증은 실패/미검증으로 보고하고 통과로 대체하지 않는다.

## 요구사항에서 검증으로 연결

1. **명세**: 사용자·권한, 입력·출력, 성공·실패 조건, 보존할 기존 동작을 정의한다. PRD의 ID와 연결한다.
2. **설계**: PK/FK, 버전, 단위·날짜, API 오류, 코드와 표시 라벨을 점검한다.
3. **구현**: 요청 범위를 최소한으로 수정한다. 다른 작업자의 변경과 운영 자료를 보존한다.
4. **검증**: 허용 사례뿐 아니라 무권한·버전 누락·충돌·실패 롤백을 확인한다. 실행한 게이트와 결과를 기록한다.
5. **전달**: 코드 커밋·푸시와 운영 배포를 구분한다. 운영 적용에는 별도의 환경·백업·마이그레이션 확인이 필요하다.

## 불변식별 검사 범위와 한계

| 불변식 | 현재 자동 검증 | 추가 확인 |
| --- | --- | --- |
| 초기화 보존 | 기존 평문/계정 상태·버전 불변, 재실행, 최초 관리자 변경 강제 | 운영 계정 복구는 별도 유지보수 절차 |
| 코드 기반 판정 | 권한 API 거절 사례 및 일부 도메인 테스트 | 모든 업무 분기를 정적으로 보증하지 않음. 레거시 라벨 비교 제거는 PRD의 정비 항목 |
| 전역 모달 | TS AST의 네이티브 함수 참조 차단, 브라우저 네이티브 다이얼로그 감시·사용자 취소 | 임의 alias·동적 실행 등 모든 우회 경로를 증명하지 않음 |
| PK/FK | PGlite 제약·고아 참조·보존/롤백 검사, JPA 연동 | H2 테스트만으로 PostgreSQL DDL 호환성을 주장하지 않음 |
| 버전·원자성 | 누락 400, 충돌 409, 연동 실패 롤백, 공지 버전 검사 | 새 수정 경로 추가 시 누락·충돌 테스트 추가 |
| 자료 분리 | CSV/전체 덤프 추적 차단, 공유 문서 BCrypt 값 검사 | 모든 개인정보의 자동 탐지는 아님. 커밋 diff·첨부·로그를 사람이 검토 |

## 브라우저 검증 격리

[runner](../tests/browser.e2e.cjs)는 127.0.0.1의 13000·18080 포트를 사용한다. 이미 사용 중이면 기존 프로세스를 종료하지 않고 실패한다. 새 H2 메모리 DB만 사용하며 PostgreSQL 운영 연결은 사용하지 않는다. 검증이 생성한 프로세스는 성공·실패 모두 정리한다.

브라우저·서버 오류 로그와 합성 데이터 화면은 `test-results/e2e/`에 저장하며 Git에 포함하지 않는다. CI에서는 실패 시 아티팩트로 보관한다. 실행 중인 운영 화면을 캡처하거나 기존 DB 자료로 테스트하지 않는다.


### 화면별 검사 범위와 제한

[화면 검사](../tests/ui-screens.e2e.cjs)는 공통 runner 안에서 합성 직원·프로젝트·계약·평가·자산·코드를 생성한다. 관리자 주요 작업과 별도 세션의 일반직원/PM 관리 버튼 제한을 확인한다. 모든 버튼·입력 조합·권한의 전수 검사는 아니다.

- 직원/조직도: 동명이인 ID 선택, 타 부서 프로젝트 참여자, 실제 사번·연락처·프로젝트 검색, 부서/직급/상태·인재풀 조합과 초기화, 빈 결과 복구, 키보드 정렬, 페이지 이동 후 검색 시 첫 페이지 복귀, 조직도 접기/펼치기, 등록·수정 저장, 퇴사 취소/실행·계정 비활성·이력 보존을 검사한다. 390/768px에서 검색·직원 선택·결과 포커스 이동, 가로 넘침과 헤더 배치를 확인한다. 전체 스크린리더 사용성과 대규모 인원 성능은 별도 확인이 필요하다.
- 주요 업무: 프로젝트 등록/수정, 계약품의서 결재자 선택/저장, PM 보고 저장/서버 재조회, 자산 등록/검색/수정/삭제 및 취소, 기존 종합평가 등록/수정/삭제, 기준정보 탭·공통코드 그룹 코드 검색/등록/수정/삭제, 연간 공수 연도 전환/검색을 검사한다. 계약 저장용 연도별 노임단가는 합성 픽스처로 준비하며 운영 단가의 정확성을 보증하지 않는다.
- 달력: 월 이동·오늘·목록/달력 전환·일정 등록을 검사한다. 현재 사용자 등록 일정은 브라우저 localStorage 저장 범위이며 서버 공유·다른 기기 동기화는 제공하지 않는다. 표본 공휴일·회사 일정의 실제 정확성은 이 검사로 보증하지 않는다.
- 모바일: 대시보드·프로젝트·보고·자산·평가·기준정보의 390px 진입과 문서 가로 넘침을 검사한다. 각 화면의 모든 모바일 편집 조합, 외부 전화/메일 발신, 인쇄 및 실제 운영 연동은 실행하지 않는다.

실행 결과의 `test-results/e2e/screen-audit.json`과 조직도 데스크탑/태블릿/모바일 PNG는 Git 제외 산출물이다. 이 검사 범위와 별개로 기존 runner의 공개 포털·개인정보 초안·인증·세션·공지 게시/익명 조회·로그아웃 검증도 계속 실행한다.

### 수행평가 검증과 복귀

[EVAL-02~04](prd.md)의 검증은 [API 통합 테스트](../backend/src/test/java/com/nexus/groupware/EvaluationPlanIntegrationTest.java), [계산·SQL 테스트](../tests/evaluation-plans.test.mjs), 공통 runner가 실행하는 [수행평가 브라우저 검사](../tests/evaluation-plans.e2e.cjs)로 구성한다.

- API: 직원 본인/소속 PM/타 프로젝트 PM/임원 범위, 검색·페이지·직접 ID 요청, 본인 승인 금지, 목표 보완·재제출·승인 잠금, 실적 보완·확정, 버전 누락·충돌·동시 승인, 월별 실적 MM 합산 초과의 원자적 거절을 검사한다. 배정 종료·재투입 시 새 ID와 기존 목표 보존, 승인된 인재풀 목표가 프로젝트 투입 후에도 결과 입력 가능한지 확인한다.
- SQL: PGlite에서 V8 적용 전후 기존 프로젝트·종합평가 보존, PM/참여자 배정 중복 제거, 복합 FK와 검토자 제약, 이력 존재 시 프로젝트 삭제 거절을 검사한다. H2만으로 PostgreSQL 호환성을 주장하지 않는다.
- 브라우저: 별도 합성 계정으로 목표 작성→보완→재제출→승인→실적 제출→평가 확정을 실제 조작한다. 승인 목표·배점·계획 MM 잠금, 최종 실적 잠금, 타 직원 목록·상세 접근 제한, 인재풀 기본지표/초안, 390/768px 문서·모달 가로 넘침을 검사한다. `evaluation-locked-390.png`, `evaluation-locked-768.png`는 Git 제외 합성 화면이다.
- 복귀: 서버 스위치를 끄면 설정 응답이 false이고 신규 API가 503인 것을 검사하며, 브라우저에서는 비활성 설정 응답으로 기존 종합평가 화면이 표시되는지 검사한다. 실제 운영 재시작·DB 백업 복원 시험은 수행하지 않았다. 절차는 [롤백 안내](rollback/hr-evaluation-20261103.json)를 따른다. 적용한 V8 파일·DB 이력을 제거하지 않는다.

2026-11-03 검증은 다른 작업의 미완성 변경을 보존하기 위해 기준 커밋과 수행평가 변경만 담은 별도 작업 폴더에서 실행했다. Node/SQL 44건, Java 31건 및 프로덕션 빌드 기반 브라우저 검사가 통과했다. 이는 별도로 진행 중인 공유 작업 폴더의 다른 화면 변경이나 운영 배포를 검증한 결과가 아니다. 실제 직원 자료를 사용하지 않았다.

파일 첨부 업로드, 익명 다면평가·연간 전체 점수 합산·최종 인사 심의, 모든 모바일 편집 조합·스크린리더·대규모 성능은 이 검증 범위에 포함하지 않는다.
